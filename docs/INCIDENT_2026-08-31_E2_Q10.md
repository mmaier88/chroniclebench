# Incident disclosure — 2026-08-31: post-draft stages silently disabled; a system cohort withdrawn and re-run

This is the public, benchmark-scoped record of the incident referenced by
`data/chronicle-x-sonnet.json` (`provenance.incident`). The full internal
postmortem covers engine deployment mechanics and is not part of this repository.

## What happened

On 2026-08-31 a production deploy of Chronicle's engine silently disabled two
post-draft pipeline stages (style repair and post-hoc chapterization): the deploy
branch predated the commits that enabled them, and redeploying regenerated the
server environment from the branch's template, reverting the enablement. Both
stages are flag-gated default-off and emit nothing when disabled, so no error,
event, or cost entry surfaced, and the deploy's end-to-end validation did not
check for the stages' presence.

The six books of the `chronicle3` production benchmark round were generated
inside this window — **draft-only**, not the intended production pipeline.

## What it means for the benchmark

- The `chronicle3` round was **withdrawn before publication** and is preserved
  internally as outage-invalid. It never appeared on any board.
- The published **Chronicle × Sonnet (Production)** entry is the `chronicle3r`
  round: the SAME six frozen-brief drafts completed through the restored full
  pipeline and scored with the same pinned instrument
  (`obr-v2.1-2026-03-08`). See `data/chronicle-x-sonnet.json` and
  `data/scores/chronicle-x-sonnet/`.
- No bare-model cohort run, no human reference score, and no other board row
  was affected — the incident was confined to the Chronicle system entry's
  generation pipeline.

## Remediation (engine-side, summarized)

A stage ledger now records which pipeline stages ran on every book, the affected
flags fail closed, and deploy validation asserts the post-draft stages'
presence. Details live in the internal postmortem.
